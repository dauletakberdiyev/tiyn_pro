# Tiyn

Telegram Mini App для личного бюджета на русском языке. Основная валюта — тенге (KZT). Состав первой версии описан в [APP_V1.md](APP_V1.md).

Аудит и принципы текущего интерфейса: [DESIGN_AUDIT.md](DESIGN_AUDIT.md). Визуальный слой находится в `src/redesign.css`; он использует существующие компоненты и сохраняет финансовую модель.

## Локальный запуск

Нужен Node.js 24. Версии зависимостей зафиксированы в `package-lock.json`.

```sh
nvm use
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173`. Если переменные Supabase не заданы, приложение показывает явно обозначенный демонстрационный бюджет. Изменения сохраняются в `localStorage` этого браузера, ключ `tiyn.demo.v1`.

Кнопка «Создать свой» заменяет пример первым собственным счётом. Для возврата к примеру есть отдельное подтверждение в настройках. Локальные данные автоматически не переносятся в Supabase.

## Что реализовано

- Адаптивный интерфейс: нижняя навигация с кнопкой добавления на телефоне, верхняя навигация на большом экране.
- Счета, начальные остатки, корректировки и архивирование.
- Цели накоплений: отдельный счёт на цель, прогресс по текущему остатку, необязательный срок и ежемесячный ориентир.
- Расходы, доходы, переводы, возвраты покупок; редактирование, повтор, удаление с отменой.
- История с поиском и фильтрами; CSV за выбранный период.
- Собственные категории с цветами и иконками.
- Месячные бюджеты, лимиты категорий и темп расходов.
- Объяснимый расчёт суммы на день, резерв и исключение накопительных счетов.
- Разовые и ежемесячные планы; подтверждение фактической суммы и даты; связь с существующей операцией.
- Простые долги в обе стороны, выдача нового займа, частичный возврат и история.
- Аналитика по категориям и дням с переходом к операциям.
- Светлая, тёмная и системная темы, скрытие сумм, вибрация.
- Telegram SDK: safe area, тема, кнопка возврата и запрос права бота на сообщения.
- Серверный Telegram-вход, текстовый ввод через бота и выбор неоднозначной категории.
- Напоминания, пороги лимитов и недельный отчёт через защищённую Cron-функцию.

При отсутствии Supabase и бота работают локальные сценарии; реальные Telegram-вход, сообщения и Cron требуют настройки ниже. Серверные API, вход с синтетической Telegram-подписью, сохранение и дедупликация уже проверены на пользовательском проекте. Frontend опубликован на https://tiyn-six.vercel.app, реальный вход проверен в Telegram Desktop. Открыть: https://t.me/tiyn_pro_bot?startapp. Подробности и порядок обновления — в `DEPLOYMENT.md`.

## Подключение Supabase

### 1. Создать проект и применить миграцию

Создайте проект Supabase. Команды ниже рассчитаны на Supabase CLI 2: используйте `npx supabase@2` вместо `supabase`, если CLI не установлен. Для CLI 3 у команд базы требуется явный выбор удалённого проекта через `--remote`; подробности — в [официальном описании обновления](https://supabase.com/changelog/supabase-cli-v3).

```sh
supabase login
supabase link
supabase db push
```

Команда `link` предложит выбрать проект. Не запускайте повторный `supabase init`: конфигурация уже находится в репозитории.

Миграции: `supabase/migrations/20261112132555_finance.sql` и `supabase/migrations/20261112133215_reminders.sql`. Их версии соответствуют уже развёрнутому проекту; не переименовывайте их при повторном подключении CLI.

В настройках Supabase Auth отключите публичную регистрацию. Email provider должен оставаться включённым: сервер создаёт внутреннюю Auth-учётную запись через Admin API и обменивает одноразовый токен на обычную обновляемую сессию. Реальная почта не запрашивается, письма не отправляются. MFA и дополнительный пользовательский вход по почте в v1 не предусмотрены.

### 2. Настроить frontend

```sh
cp .env.example .env.local
```

Заполните `.env.local`:

| Переменная | Значение |
|---|---|
| `VITE_SUPABASE_URL` | URL проекта Supabase |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Publishable key проекта; legacy anon key также поддерживается SDK |
| `VITE_TELEGRAM_BOT_USERNAME` | Username своего бота без `@` |

Переменные с префиксом `VITE_` входят в публичную сборку. Service role key и токен Telegram-бота туда не добавляются.

После изменения env перезапустите dev-сервер или пересоберите frontend. Когда Supabase настроен, вход выполняется из Telegram. За пределами Telegram можно использовать уже существующую сессию; иначе приложение предложит открыть бота.

### 3. Настроить серверные секреты

Создайте своего бота через BotFather, затем:

```sh
cp supabase/functions/.env.example supabase/functions/.env.local
```

Заполните файл:

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | Случайная строка для проверки webhook; разрешены буквы, цифры, `_` и `-` |
| `CRON_SECRET` | Отдельная случайная строка для вызова напоминаний |
| `PROJECT_URL` | HTTPS URL проекта Supabase; используется скриптом настройки бота |
| `MINI_APP_URL` | HTTPS адрес опубликованного frontend |
| `ALLOWED_ORIGINS` | Точные разрешённые origins через запятую, без завершающего `/` |

Для генерации каждого секрета можно отдельно выполнить `openssl rand -hex 32`. Секреты должны различаться.

На hosted Supabase значения `SUPABASE_URL`, `SUPABASE_ANON_KEY` и `SUPABASE_SERVICE_ROLE_KEY` доступны функциям автоматически; не копируйте их в frontend или Git.

```sh
supabase secrets set --env-file supabase/functions/.env.local
supabase functions deploy telegram-login
supabase functions deploy finance-api
supabase functions deploy telegram-bot
supabase functions deploy reminders
```

В `config.toml` отключена встроенная проверка JWT gateway для этих четырёх функций. Каждая функция выполняет собственную обязательную проверку: подписи Telegram, сессии Supabase, webhook secret или Cron secret соответственно. Привилегированный доступ доступен только серверу.

### 4. Опубликовать frontend и настроить Telegram

```sh
npm run build
```

Разместите содержимое `dist/` на статическом HTTPS-хостинге. Приложение использует hash-навигацию, поэтому отдельные правила SPA rewrite не нужны. Страница должна открываться внутри Telegram без дополнительного входа в сам хостинг.

Проверьте `MINI_APP_URL`, `PROJECT_URL` и `ALLOWED_ORIGINS`, затем выполните:

```sh
npm run setup:telegram
```

По умолчанию скрипт только проверяет настройки. Для применения webhook, меню Mini App и русских команд:

```sh
npm run setup:telegram -- --apply
```

Скрипт не выводит токены. В BotFather дополнительно включите Main Mini App и задайте тот же HTTPS URL. Откройте бота, нажмите Start, создайте первый счёт в приложении.

### 5. Включить напоминания

В Supabase Vault создайте два секрета:

- `tiyn_supabase_url`: URL проекта.
- `tiyn_cron_secret`: то же значение, что у серверного `CRON_SECRET`.

Задания уже создаются миграцией `20261112133215_reminders.sql`. Для отдельной повторной настройки можно выполнить `supabase/setup-cron.sql` через SQL Editor. Расписание:

- Проверка уведомлений каждые 15 минут.
- Очистка истёкших черновиков бота и старых обработанных Telegram updates.

В приложении включите нужные уведомления и разрешите боту писать в личный чат. Время интерпретируется в выбранном часовом поясе. Доставка происходит в ближайший запуск Cron после выбранного времени.

## Как устроен backend

Для v1 выбран атомарный агрегат: одна строка `finance_books` на пользователя, содержащая JSON-состояние счетов, операций, бюджетов, долгов и планов. Это позволяет одним коммитом менять перевод, возврат долга или оплату плана вместе со всеми связанными данными.

Состояние не записывается браузером напрямую. Edge Function проверяет сессию и Telegram-привязку, валидирует команду общей доменной моделью и вызывает `commit_finance_book`. SQL-функция блокирует строку, проверяет revision и сохраняет новое состояние вместе с квитанцией запроса. Конфликт revision перечитывается и повторяется; повтор того же request ID не применяется второй раз.

RLS разрешает пользователю читать только собственный бюджет. Прямые записи и привилегированные RPC закрыты для `anon` и `authenticated`. Служебные таблицы также закрыты RLS.

| Таблица | Данные |
|---|---|
| `finance_books` | Состояние бюджета и номер ревизии |
| `telegram_links` | Проверенная связь Telegram ID и Supabase Auth пользователя |
| `command_receipts` | Квитанции для идемпотентности команд |
| `bot_drafts` | Краткоживущие черновики для выбора категории |
| `telegram_updates` | Защита от параллельной обработки повторных updates |
| `notification_jobs` | Очередь отправки и журнал уведомлений |
| `rate_limits` | Счётчики ограничения частоты запросов |

Схема рассчитана на личный бюджет; валидатор ограничивает историю 20 000 операций. Для большого многопользовательского сервиса или более длинной истории потребуется выделение операций в отдельные таблицы и пагинация. Текущая версия читает бюджет целиком и обновляет удалённые изменения при фокусе окна и каждые 30 секунд.

## Финансовые правила

Цели создаются в разделе «Бюджет → Цели накоплений». Выберите название, сумму, свободный счёт и при желании срок. Кнопка «Пополнить» открывает обычный перевод; начисленное банком вознаграждение записывайте как доход на связанный счёт. Прогресс отражает остаток на сегодня независимо от выбранного месяца бюджета. При наличии срока ориентир делит недостающую сумму на календарные месяцы включительно, округляя вверх до тенге, без прогнозирования будущих процентов. Архивирование цели освобождает её счёт для другой цели и сохраняет настройку накопительного счёта.

- Все денежные значения — целое число тиынов. Пользователь видит тенге.
- Начальный остаток и корректировки не являются заработанным доходом.
- Перевод изменяет два счёта и исключается из доходов и расходов.
- Возврат покупки уменьшает расходы соответствующей категории.
- Выдача и возврат личного займа меняют счёт и долг, не искажая обычные доходы и расходы.
- Ожидаемые доходы не прибавляются к текущим деньгам.
- Неоплаченные обязательства, включая просроченные, резервируются в пределах горизонта.
- Оплаченный план не вычитается повторно: фактическая операция уже изменила счёт.
- Накопления на исключённых счетах не вычитаются второй раз как резерв.
- Активная цель использует весь остаток связанного счёта и автоматически исключает его из суммы на день. Создание цели не создаёт финансовую операцию.
- Дневной ориентир округляется вниз до целого тенге. Отрицательный свободный остаток показывается как дефицит.
- Повторяющиеся даты 29–31 сохраняют исходный день: 31 января, 28/29 февраля, 31 марта.

## Проверки

```sh
npm run check
npm run check:edge
npm run build
```

`check` включает TypeScript и Vitest. SQL-миграция выполняется в настоящем PostgreSQL runtime PGlite: проверяются RLS, запрет прямой записи, ревизии, дедупликация, ограничения частоты запросов и захват уведомлений. Доменные тесты проверяют денежные сценарии, даты, текстовый разбор и подпись Telegram. `check:edge` проверяет типы всех четырёх Deno-функций.

Для локального запуска полного Supabase нужен Docker и Supabase CLI. Учтите, что Telegram webhook и Mini App требуют доступного HTTPS URL; обычный localhost не доступен серверам Telegram.

## Ограничения первой версии

- Нет банковской синхронизации, мультивалютности, семейного доступа, OCR, голосового ввода и ИИ-ассистента.
- Нет сложных графиков кредитов и автоматического расчёта процентов. Основной долг и проценты учитываются раздельно.
- Полноценной очереди офлайн-изменений нет. При ошибке отправки форма остаётся заполненной.
- Автоматическая доставка Telegram `sendMessage` не может иметь абсолютную гарантию «ровно один раз». Неоднозначный сетевой результат помечается `uncertain` и не отправляется повторно автоматически; такие строки нужно проверить в журнале. Финансовые команды имеют отдельную защиту от повторного применения.
- CSV содержит операции, а не полный резервный снимок настроек и планов. Резервное копирование Supabase настраивается средствами выбранного тарифа/инфраструктуры.
